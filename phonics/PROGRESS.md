## 29 October 2026 — fourth scheduled work block

Built the isolated-sound clip foundation in `clips.js` and `recording.js`, separate from word narration. It is not connected to the interface yet, and no human phoneme recordings are supplied. The teacher desk and guide correctly continue to say that these features are not available in the UI.

`LocalClipStore` uses a dedicated IndexedDB database (`lexiquest-sound-studio-clips-v1`), one model per known sound ID, and never accesses the original classroom demo's storage. Save input requires explicit rights/privacy consent, a completed preview signal, a human review confirmation, a selected model accent, supported audio MIME, a non-empty blob no larger than 1 MB, and a finite 0.1–10 second duration. Only whitelisted fields are stored; file names and arbitrary input metadata are not copied. `inspectClip` actually decodes audio to check duration, then closes its decoder. The future UI must call this before saving; record metadata alone is not content verification.

`SoundClipPlayer` creates/revokes local blob URLs, requires the current source to reach an actual ended state before marking preview completion, resets this state on replay/replacement, and releases playback/listeners on disposal. It does not autoplay or independently verify phonetic content. A saved record means teacher-labelled/reviewed here, not a professionally verified pure phoneme.

`PhonemeRecorder` requests audio-only microphone access only after explicit consent. It limits capture to 10 seconds/1 MB, prevents duplicate requests, stops tracks on stop/cancel/error, discards failed or oversized audio, and cancels late permission responses safely. Cancelling while permission is pending and stale recorder errors from an earlier session cannot start/interrupt a newer capture. Captured blobs are unsaved previews; recording does not call the clip store. The UI must implement consent, playback, human review and explicit save controls, and must call cancel on view changes/page exit.
